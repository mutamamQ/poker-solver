# Architecture

## 1. Scope and correctness claim

This repository is a correctness-first reference implementation, not a full-game commercial no-limit solver. It implements the industry-standard vanilla Counterfactual Regret Minimization (CFR) algorithm for finite two-player zero-sum perfect-recall games, an exact Kuhn-poker benchmark, and a real but deliberately small heads-up Texas Hold'em river game with exact card evaluation and a finite betting tree.

Supported Hold'em spot: fixed five-card board; two exact combo-weighted ranges; one river betting round; player 0 acts first; check/bet for the first action, fold/call when facing a bet, and check/bet after a check; one configured bet amount; no raises, blinds, rake, side pots, multiway play, earlier streets, or abstraction. These omissions are explicit. A small solver whose value and exploitability are independently checkable is preferable to a larger unverifiable tree.

Research basis: vanilla CFR and its reach equations are summarized in `research/solver_algorithms.md`; validation and NashConv conventions in `research/validation_strategy.md` and `research/exploitability.md`; evaluator frequencies/fixtures in `research/hand_evaluation.md` and `research/equity_fixtures.md`; rules/scope in `research/holdem_rules.md`; CLI choices in `research/cli_reproducibility.md`.

## 3. Generic finite-game protocol (`model.py`)

Constants: `CHANCE = -1`, `TERMINAL = -2`; players are integers 0 and 1.

`Action` is a frozen, ordered dataclass: `kind: str`, `amount: int = 0`. Its tuple identity, not display parsing, is the canonical action identity.

`GameState` is a protocol with:

- `current_player() -> int` returning CHANCE, TERMINAL, 0, or 1;
- `legal_actions() -> tuple[Action, ...]` in stable order;
- `chance_outcomes() -> tuple[tuple[Action,float], ...]` only at chance nodes;
- `child(action: Action) -> GameState`, immutable and legality-checking;
- `information_state_key(player: int) -> Hashable` only at that player's node;
- `returns() -> tuple[float,float]` only at terminals.

`Strategy = dict[Hashable, dict[Action,float]]`.

Tree invariants: finite/acyclic; exactly one node type; terminal nodes have no actions; chance probabilities are finite/nonnegative and sum to one; a key has one owner and one ordered legal-action tuple throughout the tree; keys omit hidden opponent information and preserve the acting player's observations/actions; every terminal return is finite and sums to zero.

## 4. Cards and evaluator

`cards.py` maps strict two-character strings to integers `rank*4+suit`, ranks `23456789TJQKA`, suits `cdhs`, and provides canonical formatting and uniqueness validation. Inputs are not silently case-normalized.

`evaluator.py` exposes `evaluate_five(cards) -> tuple[int,...]` and `evaluate_seven(cards)`. Categories 0..8 are high-card through straight-flush. Tie-break components follow standard descending lexicographic order; wheel high is rank 5. Seven-card evaluation directly examines rank and suit histograms, including double-trips and three-pair cases. It is pure original code with no lookup-table dependency. `scripts/crosscheck_treys.py` compares that optimized path against Treys on deterministic random cases.

The exhaustive slow test enumerates all 2,598,960 five-card sets and exactly matches the published category totals. This is supplemented by explicit adversarial seven-card vectors and a deterministic external Treys check of 100,000 categories plus 50,000 heads-up comparisons.

## 5. Equity and weighted ranges

`equity.py` defines frozen `WeightedCombo(cards: tuple[int,int], weight: float)` and `EquityResult(wins,ties,losses,total,equity)`. `exact_equity(hero, villain, board)` enumerates every unordered legal runout and returns integer counts. `range_equity` forms compatible ordered hand pairs, weights each pair by the product of original combo weights, and normalizes after blocker removal. Empty conditional mass is an error.

The 16 exact fixtures in `research/equity_fixtures.md` were generated by Treys as an external oracle. Project tests must independently reproduce their integer counts; rounded percentages are not sufficient.

## 6. Games

### Kuhn (`kuhn.py`)

Chance deals the six ordered distinct pairs from J,Q,K uniformly. The public actions use `check` and `bet` contextually: histories `cc`, `bc`, `bf`, `cbf`, `cbc` (implementation may use explicit CHECK/BET/FOLD/CALL actions). Terminal net utilities are ±1 for check-showdown/folds and ±2 for called bets. An information key is `(game_version, player, own_card, public_history)` and excludes the opponent card. The published Nash value to player 0 is exactly -1/18.

### River Hold'em (`river.py`)

Configuration contains: version; exact five-card board; initial pot `P > 0`; equal remaining stack `S`; one integer bet `0 < B <= S`; exact nonnegative combo weights for each player. Root chance outcomes are all compatible ordered combo pairs with probability `w0*w1/Z`.

Public histories and legal actions:

- empty, player 0: CHECK or BET(B);
- CHECK, player 1: CHECK or BET(B);
- BET, responder: FOLD or CALL;
- CHECK-BET, player 0: FOLD or CALL.

Terminal payoff uses a symmetric initial-pot baseline. At an unbet showdown, winner gets `+P/2`; at a called-bet showdown, winner gets `+(P/2+B)`; loser gets the negative; ties return `(0,0)`. A bet-fold gives bettor `+P/2` and folder `-P/2` because the bettor's unmatched wager is returned. This is zero-sum and measured from the start of the spot.

Information key: `(river-v1, player, sorted_own_cards, board, public_history, P, S, B)`. The dealt opponent combo is never included.

The shipped tiny spot uses two noncolliding types per player and has at most four binary information sets per player, making exact pure-response enumeration tractable.

## 7. Vanilla full-tree CFR (`cfr.py`)

The solver first exhaustively collects every information set and its action tuple; callers can additionally run `audit_game` for full structural diagnostics. Each iteration is a synchronous full-tree sweep:

1. Freeze current strategies from cumulative regrets using regret matching.
2. Traverse separately for each updating player with reaches `(pi0, pi1, pic)` and the same frozen profile.
3. At chance nodes, multiply `pic` and sum all outcomes.
4. At player nodes, recurse over every action after multiplying that player's reach.
5. At an information set I owned by updating player i, accumulate (do not immediately apply) `delta_R[I,a] += pi_-i * pic * (v_i(I,a)-v_i(I))` across all underlying histories.
6. Apply both players' complete regret deltas only after both traversals. This prevents chance-deal traversal order from changing the strategy mid-iteration.
7. Accumulate average strategy once per information set per iteration as `S[I,a] += pi_i(I)*sigma(I,a)`. Perfect recall implies owner reach is equal at every history in I; the implementation asserts this when auditing/collecting.

Regret matching clips cumulative regrets only when forming the strategy; negative vanilla regrets remain stored. There is no sampling, random seed, discounting, pruning, or CFR+ behavior.

Reported values are evaluated from the normalized average strategy, never the final instantaneous strategy.

## 8. Exact best response and metrics (`best_response.py`)

For small games, correctness outranks scalability. Gather all information sets owned by responder i, enumerate the Cartesian product of one legal action per information set, and evaluate each pure response against the opponent's fixed behavioral strategy by exact tree traversal. This automatically enforces one action across all hidden histories. The maximum is `BR_i`.

`expected_values(game, profile)` evaluates both players. `nash_conv = Σ_i [BR_i - u_i(profile)]`. For constant-zero-sum games this also equals the sum of the two BR values. The CLI labels `exploitability` as `nash_conv/2`; it also emits `nash_conv` so normalization is never ambiguous.

A hidden-bit trap game test must show that a per-history perfect-information responder can obtain +1 while the legal infoset-consistent BR value is 0.

## 9. Audit and error boundaries

`audit.py` exhaustively traverses small game trees, detects cycles, checks chance mass, action/key consistency, finite zero-sum returns, and deterministic action ordering. Public functions raise `ValueError`/`GameValidationError`, not `assert`, for invalid user/game input. Assertions may be used only for internal impossible states and tests.

No regret clipping, NaN replacement, action-size clamping, or partial result is used as silent recovery.

## 10. CLI and packaging

`argparse` commands:

- `evaluate CARD CARD ...` (exactly 5 or 7) with `--json`;
- `equity --hero C1,C2 --villain C1,C2 [--board ...] --json`;
- `solve-kuhn --iterations N --json`;
- `solve-spot CONFIG.json --iterations N --json`.

Successful JSON is sorted and contains deterministic fields only. Solver results include algorithm `vanilla-cfr`, values, `nash_conv`, `exploitability_half_nash_conv`, iterations, and normalized strategy. Errors go to stderr; exit 2 is invalid input/config, exit 1 an internal runtime failure. Full-tree algorithms have no seed flag.

`pyproject.toml` requires Python >=3.11, exposes `poker-solver = poker_solver.cli:main`, and has no runtime dependencies. Tests run with `uv run pytest`; `@pytest.mark.slow` marks exhaustive enumeration but the Definition-of-Done command runs it.

## 13. Phase 2 reconciled architecture

Phase 2 adds a finite heads-up postflop backend. “Feature-complete” means complete for an explicitly bounded input tree; it does not mean unrestricted commercial Hold'em. PokerStove is an equity oracle, not a strategy solver, and no commercial-solver parity claim is made without a machine-readable fixture.

### Scope and modules

- `mccfr.py`: external-sampling MCCFR with lazy infoset discovery and a solver-owned `random.Random(seed)`. Vanilla `CFRSolver` remains the deterministic full-tree reference.
- `multistreet.py`: immutable flop/turn/river snapshots, exact combo-weighted private deals, finite public runouts, and discrete configured wagers.
- `best_response.py`: retain exhaustive pure-strategy enumeration as the tiny-game oracle and add a supported-tree infoset-consistent dynamic path.
- `api.py` and `cli.py`: strict versioned JSON, algorithm selection, deterministic local serialization, solve and exploitability outputs.

Three-player, preflop, rake/ICM, continuous sizing, automatic abstraction, suit isomorphism, and unrestricted full-tree solving are non-goals.

### Multi-street state and accounting

`MultiStreetConfig` validates starting board/street, initial dead pot, equal effective stacks, exact private combo weights, allowed public runouts, betting mode (`no-limit` or `pot-limit`), and finite ordered wager targets. Chip amounts are non-negative integers.

`MultiStreetState` is frozen and contains private deal, board/street, acting player or chance marker, pot before current-street commitments, current-street commitments, total contributions since spot start, remaining stacks, last full-raise increment, public history, and terminal metadata. Every transition returns a new state.

`Action.amount` is the actor's new total commitment on the current street (“raise-to”). `to_call = max(committed) - committed[player]`; newly paid chips are `amount - committed[player]`. A call target is `min(max(committed), committed[player] + remaining[player])`.

In no-limit mode a target cannot exceed current commitment plus remaining stack. In pot-limit mode, maximum additional chips are `to_call + (pot + sum(committed) + to_call)`; maximum raise-to is current commitment plus that quantity, capped by stack. An all-in over the pot-limit cap is illegal. A short all-in below a full minimum raise does not reopen raising. Unequal heads-up all-ins refund unmatched excess so contested contributions remain equal.

Check-check and aggressive-action/call close a street. On closure, `pot += sum(committed)`, commitments reset, and chance selects the next configured legal board card. If either stack is zero after matched commitments, chance deals remaining streets without decisions. Fold terminates immediately.

Terminal utility is net wealth change from spot start. Let `D` be the initial dead pot, `C_i` player `i`'s total contribution, and `A_i` their award from `D + C_0 + C_1`. Then `u_i = A_i - C_i - D/2`. Ties split the contested pot and `u_0 + u_1 = 0`. This reproduces the Phase 1 river convention and avoids incorrect winner-contribution shortcuts.

The acting player's information key includes schema version, player, own cards, public board, complete public action/street history, dynamic pot/commitments/stacks, and rule/abstraction identity. It excludes opponent cards and unobserved chance outcomes. Histories sharing a key must have identical ordered legal actions.

### MCCFR contract

External sampling enumerates every action at updating-player nodes and samples one outcome at opponent and chance nodes. Its exact regret and average-policy equations must match one documented estimator and be cross-checked against analytical Kuhn behavior; CFR+ or discounting is not mixed in. Infosets are created only when visited. Stable action/chance ordering and a private seeded RNG give repeatable output on the same interpreter/platform. No cross-platform byte-identity claim is made.

Stochastic correctness uses a predeclared seed matrix against analytical Kuhn value, vanilla CFR, and exact best response. One lucky seed or iteration count is not evidence.

### Best response and exploitability

Best response chooses one action per responder information set, weighted by opponent-plus-chance counterfactual reach. Per-history maximization is forbidden. The scalable path supports only finite perfect-recall trees with identical ordered actions at every history in an infoset; unsupported cyclic/absent-minded dependencies fail closed. Exhaustive Cartesian enumeration remains the oracle on Kuhn, hidden-bit, river, and tiny multi-street profiles.

`NashConv` is the sum of unilateral improvement incentives. In this two-player zero-sum backend, reported `exploitability` is explicitly labeled half-NashConv. JSON includes both values and the convention.

### JSON and validation gates

Version 1 `solve-spot` remains accepted. Version 2 uses strict types (booleans are not integers), explicit algorithm, seed, iterations, finite ranges/runouts, and limits. Unknown fields, invalid/overlapping cards, non-finite weights, impossible actions, and oversized exact trees fail with exit status 2.

Phase 2 completion requires:

1. All 80 Phase 1 tests remain green.
2. MCCFR same-seed local output is identical and a predeclared seed matrix meets Kuhn EV/NashConv tolerances.
3. Chance mass, blockers, action legality, unmatched refunds, all-in runouts, and terminal zero-sum utility pass exhaustive multi-street tests.
4. Dynamic best response agrees with pure enumeration within `1e-12` on every tractable oracle profile, including a hidden-information trap.
5. Evaluator/equity evidence remains the exhaustive census, Treys cross-check, and exact count fixtures.
6. Runtime tests are performance regression gates only; ceilings come from measured local medians.
